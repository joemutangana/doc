FOUNDATIONS / 02

Linux basic commands

THE EVERYDAY TOOLKIT

Linux administration often follows a simple cycle: locate what you need, inspect it, make a controlled change, then verify the result.

01
⌖

Navigate the file system

The file system is organized as a tree that begins at /. Use pwd to confirm your current location, ls to inspect a directory, and cd to move between locations.

$ pwd
/home/student
$ cd Documents

Why it matters — knowing your current directory helps prevent changes to the wrong files.

02
▧

Create and manage files

mkdir creates directories, touch creates an empty file or updates timestamps, while cp and mv copy and move or rename items.

$ mkdir project
$ touch project/notes.txt
$ cp notes.txt notes.bak

Why it matters — clear structure and backups make administration safer and easier to maintain.

03
▤

View and manipulate files

cat prints file contents, less lets you read long files page by page, and tail is useful for checking the latest lines of a log.

$ less notes.txt
$ tail -n 20 app.log

Why it matters — reading logs and configuration files is a common part of troubleshooting.

04
⌕

Search for information

find searches for files by criteria, while grep searches text for a pattern. Combine them thoughtfully when tracking down a file or a setting.

$ find . -name "*.conf"
$ grep -n "Listen" site.conf

Why it matters — targeted searches are faster than opening files one by one.

05
◴

Monitor the system

ps lists process information, top provides a live view of resource use, and df reports file-system space. Check before terminating a process or changing a system.

$ ps aux
$ top
$ df -h

Why it matters — process and disk checks help identify common causes of a slow or unhealthy system.

06
⌁

Services and network information

Services are background programs that provide capabilities such as web hosting. On systemd-based Linux systems, systemctl is commonly used to inspect and manage services. Network tools such as ip show interface and address details; ping tests basic reachability.

$ systemctl status apache2
$ ip address
$ ping -c 4 example.local

Why it matters — a hosted site depends on a running service, correct network configuration, and working permissions.

!

Admin habit: inspect before changing. Read command help or the manual, verify the target path, and check the result after an operation. Some commands require elevated privileges; use them only when necessary.

AUTOMATION / 04

Shell scripting

REPEATABLE TASKS

A shell script is a text file containing commands that a shell runs in sequence. Scripts make repeatable work consistent, reduce manual steps, and can report failures instead of silently continuing.

01

Variables and input/output

Variables store values for reuse. echo displays text, while quoted variables such as "$target" help preserve spaces in file names.

02

Conditions and loops

if branches based on a test. A for or while loop repeats work across items or while a condition remains true.

03

Exit status and functions

Commands return an exit status: usually 0 means success and a non-zero value signals a problem. Functions group reusable steps into named blocks.

04

Permissions and automation

A script can be run with bash script.sh, or made executable and launched by path. Scheduled automation can use crontab, with careful logging and testing.

check-space.sh
#!/usr/bin/env bash
# Report disk space for the root filesystem.
set -u

mount_point="/"

if df -h "$mount_point"; then
  echo "Disk-space check completed."
else
  status=$?
  echo "Disk-space check failed (status $status)." >&2
  exit "$status"
fi

SECURITY / 05

Users & file permissions

CONTROL ACCESS

Linux uses users and groups to identify who is accessing a resource. Each file or directory has an owner, an associated group, and permission bits that control access for the owner, group, and others.

U

User / owner

The account that owns the file. Ownership affects which permission class applies to that account.

G

Group

A collection of accounts that can share access to files and directories.

O

Others

Accounts that are neither the owner nor members of the file's group.

What does rwx mean?

r
Read

For a file, read its contents. For a directory, list names (subject to directory search permission).

w
Write

For a file, change contents. For a directory, create, remove, or rename entries when other requirements are met.

x
Execute / search

For a file, run it as a program if its format and other requirements allow. For a directory, traverse it.

Read a permission string

-rw-r--r--

- rw- r-- r--

The first character indicates the file type. The next three bits belong to the owner, then the group, then others. This example is a regular file with mode 644.

The explorer shows the basic nine permission bits. Special bits such as setuid, setgid, and sticky bit are not included.

755
Owner can modify; everyone can read and traverse/execute.

Common for directories and executable programs when public read/traverse access is appropriate.

chmod 755 folder
644
Owner can edit; group and others can read.

A common choice for ordinary website files that visitors and the web server need to read.

chmod 644 index.html
600
Only the owner has read and write access.

Useful for private files that should not be readable by other local accounts.

chmod 600 private.txt
!

Security principle: give each account only the access it needs. For a static Apache site, the web server needs to read files and traverse their parent directories; it usually does not need permission to modify the site's content. Use chown to change ownership and chmod to change permission bits, and verify with ls -l.
